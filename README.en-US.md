# GeyserRefine

Extra features for Bedrock (Geyser) players on a Java server. Combat is only one part; it also covers client experience, UI and assist settings.

Ideas and parts of the implementation are inspired by [GeyserExtras](https://github.com/GeyserExtras/GeyserExtras).

## Features

### GeyserRefine-Paper (Server)

Applies to Bedrock players; players who enable "Java Attack" in settings use the vanilla timing.

- Attack speed: removes the 1.9 attack cooldown for spam-clicking
- Melee: weapon damage, sprint crits and health regen tuned toward Bedrock feel
- Knockback tuned toward Bedrock (players and mobs); knockback-resistant targets stay vanilla (ender dragon, wither, warden, iron golem, end crystal, boat, minecart, armor stand)
- Cross-type combo protection: repeated hits against Java-combat opponents decay in damage, so the no-cooldown advantage is limited; not applied to mobs or Bedrock-vs-Bedrock
- Hit feedback: plays the Bedrock hit sound on a melee hit
- Hides 1.9+ effects Bedrock doesn't show (sweep, damage indicators)
- Auto-adjusts block interaction range for touch/controller/keyboard

### GeyserRefine-Extension (Client)

Bedrock-facing UI and client features:

- The pause menu's "Server Settings" opens integrated settings, with one-click quick reconnect
- Assist settings: night vision, screen coordinates, days played, mining particles, advanced tooltips, custom skulls, link prompts, etc.; attack settings appear when paired with Paper
- Main menu: quick reconnect, progress, stats, assist settings, UI settings, freecam
- Night vision: persists while on; does not stack if already granted another way
- Screen coordinates and days played default to on and persist across reconnects
- Freecam: detach the camera and fly around (WASD / space / sneak / sprint)
- Configurable join toast
- Optional resource packs and cape display (experimental)

## Installation

1. Put `GeyserRefine-Paper.jar` into `plugins/` (requires floodgate-spigot; packetevents optional).
2. Put `GeyserRefine-Extension.jar` into Geyser's `extensions/`.
3. If both are on the same machine they pair automatically; restart server and Geyser afterwards.

## Installing only one part

Both ends pair automatically over local TCP; pairing gives the full feature set. Each side also works on its own:

- **Paper only**: combat-related changes apply; `/geyserrefine settings` opens the built-in form (toggle Java/Bedrock attack only).
- **Extension only**: UI/assist features apply; attack settings are hidden (no matching server side).
- **Both**: everything, including attack settings.

Simply put: one side handles server mechanics, the other handles client experience; each works alone, together they are the complete package.

## Commands

`/geyserrefine` (alias `/gr`)

- `settings`: open settings (full menu when paired; "toggle Java attack" when not)
- `reload`: reload config
- `escape`: get un-stuck

## Config files

| File | Part | Purpose |
|------|------|---------|
| `plugins/GeyserRefine/config.yml` | Paper | combat values, knockback, combo protection |
| `plugins/GeyserRefine/playerdata.yml` | Paper | player "Java attack" setting |
| `extensions/geyserrefine/config.yml` | Extension | freecam toggle etc. |
| `extensions/geyserrefine/toast.yml` | Extension | join toast title/content/toggle |
| `tcp.properties` (both) | Both | TCP port, toggle, logging |

## Modules

| Module | Type | Role |
|--------|------|------|
| GeyserRefine-Paper | Paper plugin | server-side mechanics |
| GeyserRefine-Extension | Geyser extension | client features and UI |

## Building

Requires JDK 17 and Maven.

```
mvn clean package
```

Output:
- `GeyserRefine-Paper/target/GeyserRefine-Paper.jar`
- `GeyserRefine-Extension/target/GeyserRefine-Extension.jar`

## Dependencies

All `provided`, not bundled:

- GeyserRefine-Paper: paper-api, floodgate api, packetevents (optional)
- GeyserRefine-Extension: geyser core, gson

## Module communication

- Paper runs a local TCP server (default port `25567`, see `tcp.properties`).
- Extension connects to that port as a TCP client to sync settings such as `java-attack`.
- Without a connection both sides degrade to standalone mode (see "Installing only one part").
